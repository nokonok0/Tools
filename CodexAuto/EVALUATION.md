# 振り分けの教材と評価

## 方針

実チャットから、今回の依頼と直前の会話を組にして抽出する。過去に使用したモデルやアシスタントの成功宣言を正解として使わない。これはモデルの重みの追加学習ではなく、判定基準を評価・調整するための教材作成である。

## 暫定ラベル

- `luna`: 挨拶、完了後の謝辞、既知のパスの提示、短い翻訳・文案・説明など。背景が研究やプログラムでも、それだけでSolにしない。
- `sol`: 根本原因の調査、複数箇所に影響する実装、研究設計、重要データの変更や認証の扱いなど。
- 未記入: 文脈不足、添付の確認が必要、承認対象が不明、どちらで十分か未確認。評価の分母に含めない。

「続けて」「そうして」は単語だけで分類しない。実行対象を文脈から確認し、不足時は保留する。過去の危険な操作や完了済み作業を、今回の操作と取り違えない。

ラベルは初めはアシスタントによる仮説であり、実際のモデル間の品質・速度比較で立証済みという意味ではない。ユーザーの訂正や実行結果で見直す。medium以上を自動で選ぶ教材にはしない。

## ローカル操作

```powershell
uv run --locked python -m codex_auto.evaluation extract --limit 160
uv run --locked python -m codex_auto.evaluation evaluate --split calibration
uv run --locked python -m codex_auto.evaluation evaluate --split evaluation
```

本文と結果は `%LOCALAPPDATA%\CodexAuto\evaluation` にだけ保存する。既存教材は上書きしない。リポジトリ内へコピー、コミット、外部送信しない。抽出は最近更新された最大30ファイルをストリーム読み取りし、各会話の末尾から最大20例、全体で指定件数までとする。原ログは変更しない。

`examples.json` は教材。`labels.json` は例のIDをキーに、`expected`（`luna` / `sol` / 未記入）、`rationale`、`label_source`を記録する。教材本文とラベルは分離して保持する。

会話ファイル単位の安定ハッシュで調整用と評価用を分離し、完全一致する依頼は重複除外する。ただし、分岐会話・類似表現による漏洩を完全に防ぐものではない。採用判断前に追加点検する。原ログのツール出力、添付本体は取り込まないため、それらが必要な例は保留する。

評価はループバックのOllayaだけを使い、Codexへの推論要求は出さない。結果には本文を含めず、ID・期待値・判定値・判定理由を記録する。通信失敗によるSol選択も別記する。`luna->sol`の過剰選択と`sol->luna`の過小選択を分けて確認する。

調整用で分類の説明や文脈の渡し方を比較してから、評価用を使う。一度結果を見て調整に使った評価例は、次回の未使用評価には数えない。少数の暫定ラベルの一致率を一般的なモデル品質と呼ばない。本番適用、重みの学習、自動的な自己更新はこのツールでは行わない。
