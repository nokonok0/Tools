# Codex Meter

Codexの利用枠の残量と、モデル・推論設定ごとの実測に基づく「上限までの推定時間」を表示するWindows用トレイアプリです。

## 導入・起動

Windows、Python 3.11以降、uvが必要です。このフォルダで一度だけ次を実行します。

```powershell
uv sync --locked --python 3.11
```

`uv.lock`に基づいて専用環境`.venv`が作られます。その後は`CodexMeter.pyw`をダブルクリックしてください。起動のたびにuvを実行したり、パッケージをインストールしたりすることはありません。

通常のウィンドウやタスクバー項目は表示せず、時計横のトレイに常駐します。

- アイコン内に直近モデル・推論設定の短期枠の残り推定時間を表示します（`45m`、`2.5h`など）。連続使用時の目安であり、リセットまでの時間ではありません。
- 計測中は`...`、未取得・更新待ちは`--`、上限到達は`0m`です。詳細はマウスを重ねるかクリックして確認できます。

- アイコンにマウスを重ねると、残量・リセットまでの時間・直近モデルの短期枠の推定時間を表示します。
- クリックすると、現在のモニターのタスクバー付近に小さなパネルを表示・非表示にします。
- パネルの外をクリックする、Escapeを押す、またはパネルを閉じると非表示になります。
- 右クリックメニューから表示・非表示、更新、終了を操作できます。
- 再度起動した場合は、重複起動せず既存のパネルを表示します。
- pystrayがない環境では通常のウィンドウとして動作し、閉じると終了します。

## 通常／軽量の一括切替

パネル右上の「通常／軽量」ボタン、またはトレイの右クリックメニュー「軽量モード（Meter共通）」で、Codex MeterとDeepSeek Meterをまとめて切り替えます。起動中のもう一方へ約1秒で反映し、再起動後も維持します。ウィジェットの寸法は変えません。

- 通常は10秒、軽量は30秒ごとにログを確認して再集計します。軽量時は表示・通知の反映も遅くなります。新規ログの探索間隔など、既存の読み取り条件は変えません。
- ログを間引いて保存する設定ではありません。各ログ内の記録時刻を用いる活動区間の判定・推定式と履歴保存は共通です。読み取り上限など既存の制約は残ります。
- 「更新」はどちらのモードでも待機を解除して実行します。残高の自動取得は5分ごとのままです。
- 共通設定は`%LOCALAPPDATA%\MeterCommon\runtime.json`に保存します。追加の常駐プロセスや予定タスクは使いません。
- RunCatの設定は連動させません。FPSはRunCat自身のメニューで指定します。

## 自動起動・通知の設定

Windowsへのサインイン時に自動起動する場合は、導入後に次を実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Install-Startup.ps1
```

ユーザーのスタートアップフォルダに、`.venv\Scripts\pythonw.exe`を直接起動する`Codex Meter.lnk`を作成します。サインイン時にターミナルやパッケージの同期処理は起動しません。アプリのフォルダを移動した場合は再実行してください。自動起動を無効にするには、スタートアップフォルダのこのショートカットを削除します。

最新の観測値で残量が20%・10%以下になると、トレイ通知を表示します。各閾値・リセット期間につき一度だけ通知し、重複防止情報は`%LOCALAPPDATA%\CodexMeter\notifications.json`に保存します。通知の表示可否はWindowsの通知設定にも依存します。古い観測値や期限切れの利用枠では通知しません。

## データと推定方法

- 「モデル単独」は稼働中のモデル・推論設定を先頭に強調表示し、その他はGPTの世代が新しい順、同じモデル内では推論レベルを低い順に表示します。稼働情報が不完全な場合は先頭への移動を行いません。

- パネルは既定の560×310（最小520×280）とし、暗色基調にアクセント色を加えたコンパクトな表示にする。利用枠は大きな残量％・細いバー・リセット時刻に集約し、表の下に説明文を置かない。

- 比較表に短期の「消費率 (%/時)」と残り推定時間を表示します。Codexは共有枠100%に対する消費率、OpenRouterは今回の計測開始残高を100%とする消費率です。異なる残量の持ち時間の比較であり、料金・性能の優劣ではありません。
- 7日枠には「5h枠 あとN回」を表示します。完了した5時間枠ごとに「週間枠の消費 ÷ 短期枠の消費 × 100」を求め、その中央値を1回分の週間消費とし、残りの週間枠を割った回数です。5時間枠を使い切る想定で、週間枠のリセットまでに使える回数を上限とします。履歴が不足しているときは「あと—回」です。
- OpenRouter残高の時刻・購入総額・使用総額・残額・キーのハッシュを観測ファイルへ保存します。5分ごとの残高取得間に、単一の既知OpenRouterターンが継続している区間だけを学習します。2区間以上・実測10分以上・$0.001以上の消費で推定を表示し、それまでは計測中です。15分超の取得間隔、並行実行、モデル混在、チャージ、キー変更、使用総額の減少を除外します。チャージやキー変更では基準残高と学習を更新します。別端末での消費や請求反映の遅れは推定へ影響します。

- OpenRouter全体の残りクレジットをUSDでパネル上部とトレイのツールチップに表示します。5分ごと・更新ボタンで`https://openrouter.ai/api/v1/credits`を取得し、購入済み額から使用額を差し引きます。DeepSeek専用残高ではありません。失敗時は前回値を「更新待ち」と表示します。
- 認証は`OPENROUTER_API_KEY`を優先し、未設定なら`%CODEX_HOME%/codex-router/openrouter-api-key.secret`（既定は`%USERPROFILE%/.codex`配下）の既存キーを読みます。キーそのもの、API応答全文は保存しません。APIが401/403を返す場合は認証・残高取得権限の確認が必要です。

- DeepSeekなどの`token_usage_record`を持つモデルは、入力・キャッシュ・出力・合計トークン数をモデルと推論設定ごとに記録します。表の「トークン」列に表示します。呼び出し単位の値だけを加算し、累積値は加算しません。
- 合計は読み取れた記録分と退避済み履歴の累計で、未取得の全履歴・請求額ではありません。モデル情報より前の使用量は帰属を推測せず除外します。OpenRouterモデルにはCodexの利用枠から残り時間を推定しません。

- `%CODEX_HOME%\sessions`、未指定なら`%USERPROFILE%\.codex\sessions`の既存セッションログを読み取ります。OpenRouter残高の取得だけにAPIキーとネットワーク通信を使います。CLI起動、MCPサーバー、推論リクエストは使いません。
- 利用枠はアカウント・枠全体で共有され、モデルごとの独立した残高ではありません。推定時間は「そのモデルと推論設定だけを、観測された消費速度で連続使用した場合、現在の共有残量があとどれだけ持つか」を表します。
- 初回は最近更新された最大64ファイルについて、それぞれ末尾1 MiBまで読み取ります。その後は追記分だけを、1ファイル・1回につき最大2 MiBまで読み取ります。バックグラウンドで10秒ごとに確認し、ファイル一覧は1分ごとに更新します。
- モデル別の消費量は、観測区間全体で既知の作業がちょうど一つだけ実行中の場合に算出します。混在・並行作業、モデル不明、180秒超の観測間隔、利用枠のリセット、消費率の減少、期限切れ、データ欠落は除外します。対象が64ファイルを超える場合は、不完全なデータから推定せず予測を停止します。
- 消費速度の算出には、実測3分以上・5区間以上・3パーセントポイント以上の消費が必要です。消費率が変化しない区間も含めます。表示する推定範囲は残量のパーセント表示の丸めだけを考慮しており、作業の複雑さによってさらに変動します。実測に基づく目安であり、保証ではありません。
- 完了しなかった作業は、最後の観測イベントから3分経過すると実行中ではないと扱います。新しい活動があれば期限を延長します。他の端末やクラウドでの作業はローカルログから観測できないため、その消費がモデル別の算出や予測に影響する場合があります。
- ログはCodexの活動中に更新されます。利用枠の観測が5分間ない場合やリセット予定時刻を過ぎた場合も、直前の残り推定時間・消費率・100%使用時間・残量を消さず「※前回値」と観測時刻を添えて表示します。古い残量を現在値とみなしたり、リセットで補充された残量を仮定したりしません。トレイも前回の時間を灰色で残します。
- 短期枠・週間枠のデータがない場合は、利用可能な値として表示しません。OpenRouterはCodex枠の代わりに残高の実測を使い、それ以外の独自プロバイダーは推定しません。

## 全体・構成の計測

パネルの表示切替で「全体・構成」と従来の「モデル単独」を選べます。既定は全体・構成です。外枠は560×310のままです。

- 「全体・直近15分」は、観測区間の全体が活動で覆われる部分のアカウント消費率です。並列作業や構成変更を含め、経過時間を一度だけ数えます。休止時間は除き、同じペースで連続使用した場合の残り時間を推定します。トレイの時間もこの全体ペースを使います。
- 直近15分は最終観測時刻を基準にするため、席を離れても集計が時間経過だけで空になりません。表示した推定の数値と観測時刻をローカルの`last_forecasts.json`へ保存し、再起動後や新しい推定の記録不足時にも「※前回値」として参照できます。上限到達時は残りを0とし、消費率・100%使用時間は残します。この表示保存から学習用の実測データへ数値を逆流させません。
- 一覧の先頭行は「全体：モデル / 推論 ×人数」として現在の稼働構成を示します。長い構成は表の行内で短縮表示します。稼働がなければ「稼働なし」、ログ読取不足なら「構成未確認」です。この行の消費率は最終観測までの15分の活動平均なので、現在の構成へ切り替える前の消費も含みます。
- 構成の行は、モデル・推論設定・同時稼働数が同じ区間の全期間平均です。例えば同じモデルの子が2つ動いていれば人数として区別します。「現在」はログ上の活動から推定する構成で、実際のトークン生成やCPU稼働を示すものではありません。
- 親子と独立チャットの区別は行いません。他チャットもアカウントの利用枠を使うため、同時実行全体に含みます。個々の親・子への利用枠消費の配分や、役割別の費用は表示しません。モデル単独の学習条件は維持します。
- 直近・構成別とも実測3分、5区間、3パーセントポイント以上を必要とします。構成が変わるとその構成は新たに計測し、記録不足を単独モデルの足し算で埋めません。直近15分のペースは構成変更の影響が混ざるため、構成別の平均と使い分けてください。
- リセット・消費率の逆転・読取不足・モデル不明の区間は保守的に除外します。利用枠の表示丸めや、別端末・クラウドでの未観測の使用が予測へ影響します。作業の複雑さで速度は変わり、研究室で使える残り時間の保証ではありません。
- 構成別累計はローカル履歴の退避後も保持します。直近ペースと現在構成は詳細履歴から再計算します。OpenRouter残高は従来どおり別計測で、Codex全体へ合算しません。

## 委任の実績

表示切替の「委任の実績」で、子エージェントへ任せた作業の結果を確認できます。パネルの寸法は560×310のままです。

- `%CODEX_HOME%\delegation\runs` と `lessons`（未指定時は `%USERPROFILE%\.codex` 配下）を約10秒ごとに読み取ります。集計キャッシュには依存せず、元の記録・スキル・セッションログは変更しません。連携のための推論や通信は行いません。
- 通常作業 `work` の完了記録だけを、分類・リスク・手順の版・モデルと推論設定ごとに集計します。初期設定、比較試験、未分類の旧記録は除外し、件数を表示します。実行中は別に数えます。
- 一覧には件数、合格件数、手直し件数、親＋子の観測トークン中央値、所要時間中央値、変更前後の比較状態を表示します。観測が欠けた消費量は「未取得」です。
- 変更前後の数値は `learn` で根拠を登録した変更だけを対象に、同分類・同リスクで一要素を変えた前後を比較します。変更前の指定記録までの直近10件と、変更後の指定記録以降の直近10件について、各3件以上から「参考比較」を表示します。トークンの比較には前後それぞれ親子の観測が3件以上必要です。件数不足・根拠不足は「記録不足」です。難易度の差は未補正で、課金額の削減率ではありません。
- 失敗または手直しが2件連続した時と、登録済みの変更で前後各3件がそろった時に通知します。環境だけが原因の失敗は連続失敗の通知から外します。同じ連続不調・同じ比較を繰り返し通知しません。初回起動時に既に存在する注意は通知しません。
- 通知済みの識別子だけを `%LOCALAPPDATA%\CodexMeter\delegation_notifications.json` に保存します。委任の説明文・証拠・会話本文はMeterの履歴へコピーしません。記録が破損している場合は読取不完全を明示し、比較と通知を止めます。

## 保存情報・プライバシー

「100%使用時間」は保存済みの消費率から100%を使い切る連続使用時間を計算します（100 ÷ %/時間）。現在の残量や更新待ち状態には依存しません。Codexは短期枠、OpenRouterは計測開始残高が100%の基準です。行を選ぶとCodexの週間枠の100%使用時間も確認できます。記録不足は「計測中」です。保存期間内の実測に基づく目安で、リセットによる補充は含みません。

`%LOCALAPPDATA%\CodexMeter\observations.json`に保存するのは、許可したモデル名、推論設定、時刻、作業の開始・終了、利用枠の識別子、消費率などの観測情報だけです。会話本文、コード、パス、認証情報、アカウントIDは保存しません。セッションファイルのパスはハッシュ化します。

日数・件数による自動削除は行いません。保存は原子的な書き込みで行い、最大2分に一度と終了時に実施します。元のログには会話が含まれる場合がありますが、取り込むのは上記の構造化された情報だけです。既存のCodexファイルは変更しません。旧版が既に削除した記録は復元しません。

起動時に `observations.json` が100MB（100,000,000バイト）を超え、登録済みの退避先と一致する場合は `N:\CodexMeter\` に日時・一意ID付きJSONとして退避します。ドライブ文字だけで判断せず、Windowsが解決した実パス（ネットワークドライブならUNCパス）を登録時と比較します。コピーにも実パスを使います。未登録・接続先変更・未接続・失敗・読取不完全の場合は退避せず、ローカル保存を続けます。コピー、書き込み完了、SHA-256一致確認を経てからローカルを更新します。

初回・意図した共有先への変更時は、エクスプローラーなどでNドライブの共有先と閲覧権限を確認し、CodexMeterフォルダで次を実行してください。登録はローカルの `%LOCALAPPDATA%\CodexMeter\archive_destination.json` のみを更新し、履歴をコピーしたり共有先にフォルダを作ったりしません。

```powershell
uv run --locked python history_archive.py --register N:\CodexMeter
```

登録後はアプリの次回起動から退避先を確認します。同じUNC名のサーバーや共有自体が置き換わった場合の識別・アクセス権の保証は行いません。退避ファイルには利用履歴・残高情報が含まれるため、共有先の閲覧権限も管理してください。

退避はその時点のローカルファイル全体のスナップショットです。ローカルには直近1日分と境界をまたぐ作業を残し、それより古い記録はモデル別の使用時間・消費量・区間数・トークン数などの累計に置き換えます。退避後も全期間平均の推定を継続し、元ログの再読込による二重加算を防ぎます。退避ファイル同士には重複があるため、そのまま合算しないでください。履歴閲覧の専用画面はなく、JSONを直接参照できます。
